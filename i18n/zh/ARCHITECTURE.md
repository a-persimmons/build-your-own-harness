# 从零构建 Harness — 架构

## 运行目标

仅在本地运行。开发者在自己的电脑上，通过 `uv run python run.py` 运行各层。这里描述的是教程中的 Agent 程序，不涉及服务器或云端部署。

## 外部依赖

| 服务 | 用途 | 从哪一层开始需要 |
|---|---|---|
| Anthropic API | 主要 LLM 供应商 | 第 1 层 |
| OpenRouter | 多供应商网关，兼容 OpenAI 接口 | 第 1 层 |
| OpenAI API | 可选的第三个供应商 | 第 1 层 |
| SQLite | 长期记忆存储 | 第 4 层 |

## 目录结构

**分层单体仓库（monorepo）。** 每一层有独立目录，并扩展前一层：

```
build-your-own-harness/
├── SPEC.md
├── ARCHITECTURE.md
├── CLAUDE.md
├── README.md
├── layer-01-api-shell/
│   ├── src/
│   ├── tests/
│   ├── run.py
│   └── README.md
├── layer-02-tools/
│   ├── src/        ← imports from layer-01 src/
│   ├── tests/
│   ├── run.py
│   └── README.md
└── ...
```

每个层目录都是独立的 `uv` 项目，有自己的 `pyproject.toml` 和 `.venv`。后续层通过相对路径或本地安装包，导入前面层的 `src/` 中的代码。

## 核心原则

- **函数式核心、命令式外壳**：纯函数处理逻辑；IO（API 调用、文件读取、数据库写入）放在外壳边界。
- **所有数据模式都使用 Pydantic**：包括 `Message`、工具输入输出、记忆记录；层与层之间不传递未经建模的字典。
- **在组合根进行依赖注入**：在 `run.py` 中创建 `LLMClient`、存储后端和工具注册表，再向下传入；组件内部不自行创建依赖。
- **贯彻 SOLID：**
  - *单一职责*：每个类负责一个关注点，例如客户端、注册表、记忆存储。
  - *开闭原则*：增加供应商和工具时，无需修改已有类。
  - *里氏替换*：所有供应商满足同一个 `stream()` 接口。
  - *接口隔离*：调用方只依赖自己用到的接口。
  - *依赖倒置*：高层编排依赖抽象，而不是具体供应商。
- **有目的地使用 GoF 模式：**
  - *策略模式*：供应商选择，`LLMClient` 封装可替换的后端。
  - *注册表模式*：第 2 层的工具注册表，从名称映射到处理函数。
  - *观察者模式*：第 10 层的钩子系统，在动作前后触发处理。
  - *模板方法*：第 8 层及以后的基础 Agent 循环，提供可重写的步骤。

## 关键路径

- **流式管道**：从第 1 层起就必须端到端可用，事后改造成本高。
- **工具执行循环**：第 2 层引入核心 Agent 循环，所有后续层都在其上扩展。
- **消息模式**：`Message` 模型是各层之间的数据契约，修改它可能造成不兼容。

## 边界

| 边界 | 穿过边界的数据 |
|---|---|
| 层 → LLM API | `LLMClient.stream()`：只传 `list[Message]` 与 `system: str` |
| 层 → 存储 | 仓储接口：只传领域模型，不在仓储外部编写原始 SQL |
| 工具定义 → 工具执行 | 工具注册表：只传 Pydantic `ToolInput` 模型 |
| 层 → 其他层 | `src/` 导入：只使用稳定的公开接口，不使用内部辅助函数 |

## 决策记录

| 决策 | 原因 | 日期 |
|---|---|---|
| 选择 Python 而非 TypeScript | 面向教程读者，易于上手，也能衔接机器学习生态 | 2026-04-29 |
| 非 Anthropic 供应商使用 OpenAI SDK | OpenRouter 与 OpenAI 共享相同的 REST 接口，一套代码覆盖二者 | 2026-04-29 |
| 选择 uv 而非 pip/poetry | 快速、现代、可复现；原文认为符合当前 Python 最佳实践 | 2026-04-29 |
| 第 1 层起优先支持流式调用 | 给阻塞式架构补充流式输出成本高 | 2026-04-29 |
| 所有数据模式使用 Pydantic | 在边界落实契约，支持 IDE 补全，及早发现问题 | 2026-04-29 |
| 第 4 层用 SQLite 存储长期记忆 | 本地优先、无需基础设施、可直接查看；原文类比 Google 2026 年的 “Always On Memory” 模式 | 2026-04-29 |
| 从前面层的 src/ 导入 | 展示真实的组合方式，反映生产 Harness 的增长过程，让读者理解完整路径 | 2026-04-29 |
| 默认供应商为 OpenRouter | 降低入门门槛，读者只需要一个 Key，无需为每家供应商分别准备 | 2026-04-29 |
