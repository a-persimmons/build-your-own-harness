# 从零构建 Harness — 项目规格

## 目的

提供循序渐进、可以实际运行的 Python 教程，让工程师从零构建 LLM Agent Harness，路线覆盖从 API 外壳到强化学习的全部 17 层。

## 要解决的问题

使用别人提供的 Agent 框架（LangChain、CrewAI、Mastra）的工程师，可能并不理解内部如何工作，出问题时也难以控制和调试。原文认为，当时的选择往往是黑盒框架，或者缺少可运行代码的零散博客。

## 用户

希望通过亲手实现来理解 Agent 架构的软件工程师。不要求机器学习背景；目标读者会写 Python，并至少使用过一次 LLM API。

## MVP

完成第 1–4 层并保证可运行，在根目录 README 中说明完整路线：

- **第 1 层**：API 外壳，包含多供应商客户端（Anthropic + OpenRouter）、流式调用、交互式 REPL。
- **第 2 层**：工具，包含带类型约束的工具注册表、函数调用、工具执行循环。
- **第 3 层**：上下文管理，包含 Token 跟踪、滑动窗口、摘要。
- **第 4 层**：记忆，包含短期上下文、SQLite 长期记忆，以及由 LLM 管理的检索。

每一层都有可运行的 `run.py`、通过的测试，以及解释关键设计决策的 `README.md`。

## v1 不包含的内容

- 托管或部署版本，Agent 程序仅在本地运行。
- Web UI 或前端。
- 第 5–17 层：验证 MVP 后再逐步交付。
- 微调或强化学习：位于最后的第 17 层。
- 多编程语言实现：只提供 Python。

## 约束

- Python 3.12+，使用 `uv` 管理依赖。
- Anthropic SDK + OpenRouter，支持多个供应商。
- 每层都必须能通过 `uv run python run.py` 独立运行。
- 没有截止日期。
- 原项目为 `djscruggs` 账号下的公开 GitHub 仓库。

## 质量优先级

1. **清晰**：代码要便于教学，而不只是能运行；尽量少做抽象，不追求花哨的单行写法。
2. **正确**：每层都有模拟网络的单元测试和调用真实 API 的集成测试。
3. **可维护**：分层可清晰扩展，后面的层导入前面的层，不产生循环依赖。
4. **性能**：不是优先目标。

## 设计原则

- **函数式核心、命令式外壳**：每一层都将纯业务逻辑与 IO 分离。
- **所有数据模式使用 Pydantic**：工具输入、消息、记忆记录，都在边界处进行约束。
- **SOLID**：每个类职责单一，为新供应商和工具保持扩展性，在组合根进行依赖注入。
- **在合适的地方使用 GoF 模式**：例如工具注册表的 Registry、供应商选择的 Strategy、后续钩子的 Observer。
- **红/绿 TDD**：先写失败测试再实现；单元测试模拟网络，集成测试调用真实 API。

## 待定问题

*MVP 暂无待定问题。已确定的决策：*

- 从前面层的 `src/` 目录导入，实现真实组合，而不是复制粘贴。
- 从第 2 层起默认使用 OpenRouter，降低门槛：一个 Key 覆盖多种模型。
